claude-as

One Claude, several logins. Each profile signs in to its own account and shares everything else: instructions, skills, settings, hooks, memory and transcripts.

Commands

claude-as workStart Claude signed in as the work profile.
claude-as Work -cCase doesn't matter. Anything after the name goes to claude.
claude-as -p "task"No name: use $CLAUDE_AS_PROFILE, or plain claude when it isn't set. A first argument starting with - means no name.
claude-as -- "task"No name, when the first thing for claude isn't a flag.
claude-as work --link-onlyCreate or repair the profile folder without starting Claude.
claude-as --listThe profiles on this machine. * marks the default.
claude-as --guideOpen this page.
claude-as --helpThe same explanation in the terminal.
echo $CLAUDE_PROFILERun inside a session to see which profile it is. Empty means plain claude.

What a profile is

A profile is a folder named ~/.claude-<name>. claude-as sets CLAUDE_CONFIG_DIR to that folder and runs claude. Claude Code keeps its login and account state there. Everything else in the folder is a symlink back into ~/.claude.

~/.claude

The one real copy
Shared by every profileEdit a skill, a setting or CLAUDE.md here and every profile picks it up. Plain claude uses this folder directly.

Because projects/ is shared, every profile's transcripts and auto-memory land in the same place. Anything that reads them sees every session, whichever account ran it.

Layers on top of the shared Claude

Two files in the profile folder are built on every run instead of linked, so a profile can add to the shared Claude without changing it. Edit the sources, never the built files.

CLAUDE.md
Imports ~/.claude/CLAUDE.md, then the tooling's profile.md (how profiles work), then your profile.md (your rules for every profile), then <name>/CLAUDE.md (this profile's own). The last two are optional.
Settings
The shared settings, plus <name>/settings.json, plus the browser profiles found for this profile, passed to claude with --settings. A profile can use this to deny tools or set its own environment.

Browsers

Each Claude profile drives its own Chrome and Safari profile. By default that is the browser profile with the same name, in any case, so claude-as work uses the Chrome profile Work. To use a different one, set CLAUDE_CHROME_PROFILE or CLAUDE_SAFARI_PROFILE under env in <name>/settings.json.

Chrome profiles live in folders like Profile 3, and claude-as looks the folder up from the name. A name Chrome doesn't have prints a warning. Safari has no command-line switch for profiles, so Claude opens File › New Window › New Work Window from the menu.

Common jobs

Add a profile
Run claude-as <name>, then type /login once and sign in with that account. The folder and links are created on first run. For its own rules or settings, add a <name>/ folder to your config.
Rename a profile
Quit every session using it, run mv ~/.claude-old ~/.claude-new and rename its config folder too, start claude-as new and /login again. Also update anything else that names the old folder path.
Remove a profile
rm -rf ~/.claude-<name> deletes the links themselves. It does not touch what they point to in ~/.claude.
Repair links
Run claude-as <name> --link-only. It adds missing links, rebuilds the two layered files, and warns about anything else in the folder it didn't make. It never overwrites those.

Good to know

The keychain stores a login under a name built from the folder's path (Claude Code-credentials-<hash>). A new folder name means a new keychain entry, so renaming a profile signs you out of it.

Profile names use letters, digits and dashes, and are lowercased. Work and work are the same profile.

Per-project MCP servers and trust prompts live in .claude.json, so each profile keeps its own.

Tooling and config live apart. The tooling is the claude-as skill in ~/.claude/skills/claude-as/: the script (scripts/claude-as, linked onto your PATH, e.g. from ~/.local/bin), profile.md and this page. Your config is $CLAUDE_PROFILES, default ~/.config/claude-profiles/: an optional profile.md and one folder per profile, outside the repo.
